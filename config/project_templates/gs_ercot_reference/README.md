# GS_AAYAD ERCOT Reference Structure (header-only)

This folder is a **read-only reference**, not a starter kit. It reproduces the
folder tree and file **headers/settings keys** currently used by the real
GS_AAYAD ERCOT/RTS project
(`/projects/gmlcmarkets/Phase2_EMIS_Analysis/GS_AAYAD/`), with every data value
stripped out. Every file here was generated by taking the header row (or, for
key/value settings files, the key column) of the real, currently-running
GS_AAYAD files as of 2026-09-18 — nothing in this folder was hand-typed or
guessed. Where that wasn't possible (see "Not reproduced" below) the file is
omitted rather than faked.

Purpose: give a side-by-side view of **what GS_AAYAD actually uses today**
next to **what `initialize_emis_project` expects from a new project**
(`config/project_templates/project_spec/`), so the gap between them is visible
and can be closed deliberately (see `system_input_separation_plan.md` at the
repo root, section "Template folder structure").

If you want a folder to copy and start editing for a *new* project, use
`config/project_templates/project_spec/` instead — this one is a mirror of
existing production data, not a template meant to be filled in.

## Notable things this reference reveals

1. **`Heterogeneous/` has no `system_config/`, `zones.csv`, `technologies.csv`,
   `scenarios.csv`, `devices_to_remove.csv`, or `project_spec.csv` today.**
   These are new concepts from `config/project_templates/project_spec/` / `SystemConfig`
   that don't exist in the current production data at all. Onboarding GS_AAYAD onto
   the new project-init flow means *deriving* these from the PSY system and the
   existing CSVs below, not migrating an existing file.
2. **Naming has already partially drifted toward the new convention, but not
   consistently.** Investor-level files already use `investor_belief.csv`,
   `scenario_data.csv`, `scenario_multiplier_data.csv` — the same names
   `config/investor_defaults/investors/investorN/markets_data/` uses. The
   *shared* `Heterogeneous/markets_data/` versions of the same concepts are
   still named `symmetric_belief.csv`, `symmetric_scenario_data.csv`,
   `symmetric_scenario_multiplier_data.csv` — a naming mismatch between the
   shared-default layer and the investor-override layer that predates this
   effort.
3. **`simulation_settings.csv` key names have drifted from
   `scripts/template/simulation_settings.csv`.** GS_AAYAD's real settings use
   `multi_day_market`; the new template uses `md_market`. GS_AAYAD's real
   settings also include `derating_scale` and default
   `accreditation_methodology` to `TopNetLoad`, not `ELCC`. Reconcile these
   before treating the new template as a drop-in replacement for GS_AAYAD's
   settings file.
4. **Several real inputs have no home in the new project-init structure yet**:
   `queue_cost_data.csv`, investor-level `project_capex.csv`,
   `"MACRS Schedule.csv"`, `finance_params.csv`, `sizedict.csv`, and the
   `derating_data/<scenario>/derating_dict.csv` tree. None of these appear
   under `config/project_templates/project_spec/` or
   `config/investor_defaults/` today.
5. **The real outage file is a per-project absolute path**
   (`/kfs2/projects/gmlcmarkets/Phase2_EMIS_Analysis/Correlated Outages/ThermalFOR_2011.csv`),
   supplied as `OUTAGE_FILEPATH` at the run-script level — distinct from the
   bundled `src/resource_adequacy/descriptors/outage-rates-ERCOT-modified.csv`
   default discussed in `system_input_separation_plan.md` §3.1. GS_AAYAD does
   not use the bundled default; it always supplies its own file.

## Not reproduced here

- `battery_cost_interpolation.xlsx`, `delta_irm.xlsx` — binary spreadsheets;
  see the real files under `Heterogeneous/` and
  `Heterogeneous/markets_data/` for their actual structure.
- `*old.csv` variants (`projectoptionsold.csv`, `projectexistingold.csv`) —
  superseded by the non-`old` files; excluded as dead/legacy, not part of
  "what's currently being used."
- `*_original/` market-parameter directories — superseded by the sibling
  directories without the `_original` suffix.
- The PSY/Sienna system JSON itself and its HDF5 time-series sidecar — these
  are binary/opaque and already documented as required inputs in
  `src/project_init/README.md`.
- `scripts/template/run_EMIS_template.jl` is not duplicated here; it is
  already the generic version of GS_AAYAD's real
  `HPC_Analysis_Runs/template_run/run_gs_15_years.jl` run script.
